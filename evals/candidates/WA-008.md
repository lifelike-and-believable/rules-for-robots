---
id: WA-008
title: Confirm a dependency's behaviour before relying on it
level: SHOULD
scope: core
verified-by: [review]
targets-failure: unverified-claim
observed-on: []
rationale: A change justified by an unverified assumption about a dependency's behaviour broke a receiver for five days while its tests passed (rules-for-robots#28).
sources: ["practices/working-with-agents.md"]
---
When a change depends on how a library behaves (which callback fires, threading, ordering, error paths), confirm that behaviour in the library's source or documentation for the installed version, and cite the file and line in your report. If you cannot confirm it, say so and leave the item open as unverified. A signature shows that an API exists, not what it does.
